## 1. 의도와 이유

여행자의 한 줄 요청을 해석해 제주 여행 경로를 만들고, 스스로 검증·수정하고, 말 타이핑 게임이나 목록으로 둘러본 반응을 반영해 경로를 다시 짜는 AI Agent. 제주빅데이터센터 체험형 키오스크(센터 PC)에서 돈다. (v0 1.1, D1)

이번 보완의 이유: v0과 UI 프로토타입은 데이터를 가볍게 조사한 상태에서 만들어졌다. 그래서 핵심 기능("방문이 덜 몰리는 곳 추천", 관심사 매칭, 권역 묶기)에 **어떤 데이터가 근거인지**가 비어 있었다. 이 문서는 기능과 흐름은 v0 그대로 두고, 각 기능을 허브 데이터(필요한 곳만 외부 공개 데이터)로 뒷받침하도록 고친다.

성공 기준
- 추천·검증에 나오는 모든 수치가 Tool 결과이고, 출처 데이터 ID와 기준 시점이 화면에 보인다.
- 허브 데이터가 장식이 아니라 **판단을 바꾼다**: 같은 관심사라도 방문 집중도·주변 혼잡 지표 때문에 순위가 달라지는 것을 시연할 수 있다(평가 "필수 데이터 활용" 20점).
- 센터 PC에서 인터넷이 끊겨도(LLM 없이) 규칙 기반으로 전 흐름이 돈다.

### 5.4 ETL과 매칭

순서 (`data/raw/` → ETL 스크립트 → `data/db/malttara.sqlite`)
1. **1349 정제**: 위경도가 제주 본섬 범위 밖이면 제외, 부속섬 제외, 장소가 아닌 행 제외(예: "렌트카반납", 공항·항만·주차장 등 비장소 키워드 목록 — 설정값). 지번주소에서 읍면동 추출 → `emd`.
2. **분류 붙이기**: 1349 ↔ TourAPI 매칭.
   - 정규화 이름(공백·괄호·"제주" 접두·특수문자 제거)이 같고 거리 ≤ 300m → 매칭.
   - 아니면 반경 100m 안 최근접 + 이름 유사도 ≥ 0.6 → 매칭.
   - 남은 장소: 811·812·784·858과 같은 규칙으로 매칭 → 그 데이터의 분류.
   - 그래도 남으면 이름 키워드 규칙(예: "~해수욕장/해변"→바다, "~오름"→오름, "~숲길/휴양림"→숲) → 없으면 `분류 없음`.
   - 매칭 방법을 `places.category_source`에 기록(tourapi / hub_811 / keyword / none). 임계값은 설정값이고, 매칭률은 카드 '분석 결과'에 기록.
3. **음식점**: TourAPI 음식점 유형은 1349에 없어도 `places`에 넣는다(`source='tourapi'`). 같은 정제·부속섬 규칙 적용.
4. **563 집계**: 2.4GB라 청크로 읽어 `emd × 월(1~12)` 평균 방문인구·거주인구로 줄인다. 지표 `visit_ratio = 방문인구 / 거주인구`. 연평균도 저장.
5. **1208 집계**: 장소마다 반경 1km 안의 체류 거점 수 → `quiet_count`. 6개 파일 합산.
6. **189/190**: 관광지명 정규화 후 `places`와 이름 매칭(수작업 매칭표 허용, `data/mapping/sights_to_places.csv`). 매칭된 장소만 차트에 쓴다.
7. **경계**: 읍면동 경계 → 단순화 → SVG path + 권역 외곽선 → 프론트 정적 파일.
8. `data_sources` 테이블에 데이터 ID, URL, 받은 날짜, 실제 기간, 행 수, 이용조건, 매칭률 기록.

## 6. 에이전트 설계 (v0 3장 유지 + 구체화)

구조는 v0 그대로: Plan-and-Execute, 모듈 M1~M8, LLM 판단 5곳 + 규칙 폴백, 검증-수정 최대 2회, 배치 ID, `agent_decisions` 기록.

### 6.1 조건(목표) 스키마
| 항목 | 값 | 비고 |
|---|---|---|
| nights, days | 정수 | **유일한 필수**. 없으면 확인 화면에서 입력 요구 |
| pace | 여유롭게 / 보통 / 빡빡하게 / 미반영 | 미반영이면 보통 규칙을 쓰되 화면에 "미반영(보통 기준 적용)" 표시 |
| interests | [바다, 오름, 숲, 실내·전시, 체험·레저, 음식, 카페·쇼핑 …] | 분류 매핑표(설정값)로 places.category와 연결 |
| transport | 렌터카 / 버스 / 도보 / 미반영 | 표시만. 검증은 직선거리 공통. 버스는 "노선 미반영" 한계 표시 |
| companion | 문자열 / 미반영 | 표시만(MUST 범위에서 점수에 안 씀) |

### 6.2 장소 점수 **[제안·승인]**
```
score = 0.6 × interest + 0.2 × spread + 0.2 × quiet
  interest = 장소 분류가 사용자 관심사에 해당하면 1, 아니면 0
             (관심사 미반영이면 모든 장소 1)
  spread   = 1 − (장소가 속한 읍면동의 visit_ratio 백분위)   ← 563, 범위 내 읍면동끼리 비교
  quiet    = 1 − (장소 quiet_count 백분위)                   ← 1208, 범위 내 장소끼리 비교
  지표 없음 → 0.5(중립)로 계산하고 화면에 "지표 없음"
  동점 → place_id 오름차순
```
- **한적함 요청**: 입력에 "조용한·한적한·덜 붐비는" 류 표현이 있으면(관심사 `한적함`) 가중치를 0.4 / 0.3 / 0.3으로 바꾼다(설정값). 프로필 3에서 허브 데이터가 순위를 바꾸는 시연 근거. **[Claude 판단]**
- **관심사 ↔ 분류 매핑표**(설정 파일, **[Claude 판단]** 초안): 바다 → 해수욕장·해변·포구·해안 / 오름 → 오름 / 숲 → 숲길·휴양림·공원 / 실내·전시 → 박물관·미술관·전시 / 체험·레저 → TourAPI 레포츠·체험 / 음식 → TourAPI 음식점(카페 제외) / 카페 → TourAPI 음식점 중 카페 소분류 + 이름 키워드. 실제 분류 값은 TourAPI 원본을 받은 뒤 매핑표에 채운다.
- 동행("아이와 함께" 등)은 표시만 하고 점수에 쓰지 않는다. 화면에 "동행: 아이와 함께 (점수 미반영)".
- 가중치·반경·임계값은 설정 파일. 데이터셋 버전 + 설정이 같으면 순위가 같다(재현성 정의 v0 3.7).
- 화면 표시 분리(원칙 3): `spread`의 원천은 "**○○읍 지표: 방문/거주 비율 (563, 기준 기간)**"으로, `quiet`는 "**장소 반경 1km 렌터카 체류 (1208, 2021 하반기 토요일)**"로 따로 보여준다. "이 장소는 한적하다" 같은 문장은 쓰지 않는다.
- 분류 없음 장소는 관심사가 있을 때 interest=0.

### 6.3 일정 생성 (`create_itinerary`, 코드)
1. 하루 장소 수 k: 여유롭게 3 / 보통 4 / 빡빡하게 5.
2. 권역별로 상위 k개 장소 점수 합을 구해 상위 days개 권역을 날짜에 배정(권역 하나에 하루). 권역 후보가 days보다 적으면 같은 권역을 이틀에 걸쳐 쓴다(장소 중복 금지).
3. 각 날짜: 그 권역에서 점수 상위 k개 → 최고점 장소부터 최근접 이웃 순서로 정렬(출발지 입력 시 출발지에서 가까운 장소부터).
4. 관심사에 음식이 있으면 그 날 권역의 최고점 음식점 1곳을, 카페가 있으면 카페 1곳을 넣는다(각각 하루 최대 1곳, k에 포함). 근거 표시는 "TourAPI 등록 음식점/카페"뿐.
5. 거리는 하버사인 직선거리. 화면 표기 "직선 n km (도로거리·이동시간 아님)".

### 6.3.1 작업 계획이 바꾸는 것 (`plan_tasks`, 자율적 도구 선택 근거) **[Claude 판단]**
필수 단계(조건 검증 → 장소 탐색 → 일정 생성 → 거리 계산 → 검증·수정 → 설명·저장)는 코드가 고정한다. LLM(폴백: 아래 규칙표)은 목표에 따라 다음을 더하거나 빼고 파라미터를 정한다.

| 조건 | 추가·생략 | 파라미터 |
|---|---|---|
| 관심사에 음식/카페 | 음식점·카페 탐색 추가 | category=음식/카페 |
| 관심사 없음 | 관심사 필터 생략 | 가중치 기본 |
| 한적함 요청 | `get_region_data`로 권역별 집중도 비교 추가 | 가중치 0.4/0.3/0.3 |
| 날짜(월) 입력 | 월별 지표 사용 | month=입력월 |
| 출발지 입력 | 출발지 거리 검증 추가 | origin |
| 후보에 189/190 매칭 장소 있음 | `analyze_tourism` 추가 (없으면 생략) | place_ids |
| 권역 후보 장소 < 필요 수 | 인접 권역으로 검색 확장 | region_ids 확대, limit 증가 |
| 분류 없음·지표 없음 비율이 높음 | `check_data_quality` 결과를 근거 패널에 강조 | — |

실행 로그에 "추가/생략한 Tool과 이유"를 남겨 프로필마다 다른 호출 순서를 시연한다.

### 6.4 검증 (`validate_itinerary`, 코드)
위반 목록을 만든다:
- 하루 직선 이동거리 합 > 60km (설정값)
- 하루 방문 권역 수 > 1 (빡빡하게는 2)
- 같은 장소 중복, 범위 밖(부속섬) 장소, k와 다른 장소 수
- (출발지 입력 시) 첫 장소까지 직선거리 > 설정값

### 6.5 수정 (`revise_itinerary`)
- LLM: 위반 목록과 허용 행동(같은 권역 후보로 교체 / 순서 변경 / 제외)에서 고르고 대상을 지정(JSON 스키마 강제).
- 폴백: 그 날 권역 중심에서 가장 먼 장소를 같은 권역의 미사용 최고점 후보로 교체.
- 적용·재검증은 코드. 최대 2회 후에도 위반이 남으면 위반 내용을 표시하고 사용자에게 넘긴다.

### 6.6 오류 주입 시연 (v0 6.3)
설정 플래그(또는 화면의 시연 토글)를 켜면, 초안 생성 직후 1일차에 다른 권역의 최고점 장소 1곳을 끼워 넣는다 → 검증이 "권역 수 초과 / 이동거리 초과"를 탐지 → 수정 루프가 같은 권역 장소로 교체. 예시 장소명은 데이터 확인 후 정한다(v0의 "서부 일정 중 성산일출봉"은 그 장소가 데이터에 있을 때만).

### 6.7 Batch B (재설계)
- 규칙(폴백): 꼭 갈래요 = 고정, 별로예요 = 교체(같은 권역 미사용 최고점), 관심 = 그 분류의 interest 가중 +0.2(설정값)로 재점수 → 장소 수가 k보다 적은 날에 상위 장소 추가.
- LLM: 위 집계 결과를 보고 유지·고정·교체·추가를 고른다(허용 목록·스키마 강제). 이후 재검증·수정 루프.
- `compare_itineraries`: 장소별 유지·고정·교체·추가·제외 + 이유.

## 8. 기술 구성 (v0 5.2 유지)
- 프론트 React + TypeScript + SVG(Phaser 미사용, 미리 빌드해 정적 파일로 동봉), 백엔드 **Python 표준 라이브러리 서버**(8.2), SQLite. Pandas는 ETL(개발 PC)에서만.
- 실행 중 외부 의존: Upstage API뿐. 실패·오프라인이면 규칙 폴백으로 자동 전환(로그에 판단 주체 "규칙" 표시).
- Batch 로그 전송 방식(SSE/폴링), API 경로, 차트 구현(직접 SVG 또는 라이브러리)은 **[빌더 판단]** (라이브러리 쓰면 명시 사항에 기록).
- 배포 형태 (게시판 답변 반영, 8.1 참고): 대상 OS는 Windows 11 26H2(센터 PC). 프론트는 미리 빌드한 정적 파일로 동봉(실행 시 Node 불필요). Python은 python.org 공식 설치본(서명 포함), 버전 고정(3.11). 실행 중 의존성은 최소화하고 Pandas 등 무거운 패키지는 ETL 전용 requirements로 분리(심사위원은 ETL을 돌리지 않음). 실행 스크립트 하나(`run.bat`)로 서버 기동 + 브라우저 열기.

| 서명 없는 확장 모듈 | 디지털 서명 없는 오픈소스 패키지와 `.pyd`·`.dll`은 센터 보안정책으로 실행이 제한될 수 있음. 센터 탑재 시 운영자 허용 등록 가능. 전문가 평가 때 허용 등록을 해 주는지는 명확한 답 없음 | 실행 중 확장 모듈 위험 → 8.2에서 표준 라이브러리 서버로 해결 |

| 평가 데이터 | 기능 확인용 더미·샘플 데이터 첨부 권장 | 테스트 프로필 3종과 시연 시나리오 동봉 |

### 8.2 실행 중 백엔드 구성 **[확정]**
- 문제: FastAPI는 pydantic-core(서명 없는 `.pyd`)에 의존한다. 평가 PC에서 이 모듈이 막히면 프로그램이 시작되지 않고, 참가자에게 연락도 오지 않는다.
- **결정: 실행 중 서버는 Python 표준 라이브러리만으로 구성한다.** `http.server`(ThreadingHTTPServer) + `sqlite3` + `json` + `urllib.request`(Upstage OpenAI 호환 API 호출). python.org 공식 설치본에 들어 있는 모듈만 쓰므로 서드파티 확장 모듈이 없다.
- 실행 중 `requirements.txt`는 비어 있어야 한다(pip 설치 단계 없음). ETL용 `requirements-etl.txt`(pandas 등)는 개발 PC 전용.
- 라우팅(경로 → 핸들러 표), JSON 입력 검증(필수 키·타입 확인 함수), 정적 파일 서빙(빌드된 프론트), 배치 로그 스트리밍(SSE 또는 짧은 폴링)은 직접 구현 **[빌더 판단: 방식]**.
- 테스트는 표준 `unittest`로 써서 실행 환경에서도 그대로 돌 수 있게 한다(pytest는 개발 편의용으로만 허용).
- 검토했으나 버린 안: FastAPI 유지 + 매뉴얼에 허용 등록 패키지 기재. 평가 때 허용 등록이 안 되면 실행 불가.
