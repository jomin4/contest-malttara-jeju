# 기획 검토 체크리스트

설계 문서 승인 전에 한 번, 제출용 기획서(`docs/02_proposal/`) 완성 전에 한 번 점검한다.
근거: `docs/00_contest/02_규칙_제출물.md`, `03_평가기준.md`. 상호평가(30%)는 **기획서만** 보고 이뤄진다.

## 1. 대회 기획서 필수 항목 ↔ 기획문서_v0 위치

| 필수 항목 | v0 위치 | 상태 | 빈틈 |
|---|---|---|---|
| 구현목표: 분석 주제, AI 데이터 분석 목표 | 1.1, 1.2 | 있음 | 분석 목표가 D3 확정 후 구체 지표로 바뀌어야 함 |
| 서비스 제안: 데이터 활용 개요, 핵심 기능, 편의성, 분석데이터 활용 방안 | 2.1~2.5 | 대부분 있음 | "분석데이터 활용 방안"이 D3 미정으로 비어 있음. 센터 활용 방안은 2.1에 한 줄 |
| Agent 개발 구성: 역할·목표·Workflow, 사용 모델, Tool/API, 판단·자율 범위 | 3.1~3.9 | 있음 | 장소 점수 공식 없음(open-questions 2) |
| 데이터 활용 계획: 필수 데이터명·출처·활용 항목, 수집·전처리, 이용조건 | 4.1~4.6 | **D3 미정** | 데이터명·ID·URL 표, 활용 컬럼, 가공 데이터 제출 가능 여부 |
| 개발·탑재 계획: 구현 범위, 기술 환경, UI 구성, 센터 실행환경·외부 의존성 | 5.1~5.4 | 있음 | **UI 구성**이 v0에 없음 → 프로토타입 기반 화면 구성도 추가 필요 |

## 2. 배점 기준별 근거 점검

| 평가 항목 (배점) | 기획서에서 보여줄 근거 | v0 상태 |
|---|---|---|
| 기술성·완성도 (25) | Plan-and-Execute 구조, Tool 17개, 검증-수정 루프, 폴백 | 있음. 그림 1장으로 정리 필요 |
| 편의성·실용성 (25) | 필수 입력 1개, 목록 모드, 키오스크 시나리오, 대기 중 로그 | 있음. 화면 예시 필요(UI 구성) |
| 필수 데이터 활용 (20) | 데이터 ID·출처 표, 데이터가 판단을 바꾸는 예(분산형 추천) | **D3 확정 후 작성** |
| 주제 타당성·창의성 (15) | 메트로타이핑식 경로 퀘스트, 분산형 발견, 제주 관광 문제와의 연결 | 있음. 문제 정의(왜 분산 추천인가)가 약함 |
| 신뢰성·재현성 (15) | 배치 ID, agent_decisions 기록, 테스트 10종, 프로필 3종, 오류 주입 | 있음 |

## 3. 원칙 위반 점검 (설계 문서·화면 예시·기획서 모두)

- [ ] LLM이 만든 수치가 없다 (원칙 1). 화면 예시의 km·%·시간이 Tool 결과인지 표시했다
- [ ] 사용자가 입력하지 않은 날짜·출발지·이동수단을 채워 넣은 예시가 없다 (원칙 2)
- [ ] 지역 통계를 장소 속성처럼 쓴 문장이 없다 (원칙 3)
- [ ] 직선거리를 이동 시간으로 쓴 곳이 없다 (원칙 6)
- [ ] 데이터로 확인하지 않은 장소·메뉴를 예시로 쓰지 않았다
- [ ] 외부 서비스(Solar API, 지오코딩, 글꼴, 아이콘, 지도 경계 데이터)를 모두 명시했다

## 4. 설계 문서 승인 전 최소 조건

- [ ] D3·D4 결정과 근거 데이터 ID
- [ ] 장소 점수 공식과 권역 정의
- [ ] 화면 흐름(D10)과 각 화면에서 호출하는 Tool
- [ ] Tool 입출력 스키마 초안(최소 P0)
- [ ] MUST 범위가 11/18 밤 기능 동결 안에 들어가는지 A/B 트랙별 확인
